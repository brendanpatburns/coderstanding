# Components

One line each: name and short description.

- Graph model (`scanner/coderstanding/model.py`): nodes (with size and warnings; a file-level unit such as a module is sized by its file's lines outside its types, set in `resolver.add_declarations`, the one place sizes are set), edges, calls (per calling function and called member), members (functions carry first and last line), locations and their merge rules; a node's function names and a call's calling/called function
- Graph file (`graph_json.py`): read and write graph.json (and the names index `names.json` beside it) (another scanner version's map is refused, so it gets rescanned); `graph_summary` = counts and scanner version without building the model
- Language module contract + registry (`language.py`): what a language reader gets and returns, and how it plugs in; modules may reset in-memory state in `start_scan()`; `ctx.file_exists()` probes a repo file (a missing one becomes a cache dependency); `exports`/`star_exports` (names a file offers beyond its children); `read_path_map()` once per scan (import path aliases)
- Language modules (`languages/`): one reader per language, auto-loaded; tree-sitter readers share `ts_util.lifted_children` (read declarations inside ERROR nodes) and `first_error_line` (the file's `parse_error_line`); Kotlin retries a failed parse with soft-keyword names in backticks and reads a loose `class X {` header from an ERROR part; C# `[GlobalClass]` classes are global aliases so GDScript finds them by bare name
- Paths (`paths.py`): repo-relative path helpers (res://, relative paths, Godot root)
- JS/TS project config (`tsconfig.py`): import path aliases read once per scan: tsconfig/jsconfig `baseUrl`/`paths`/`extends` (JSONC), workspace package names; `PathMap.bases` = the candidates for a non-relative import path
- File walk (`filewalk.py`): finds the files to scan and which modules read them
- Resolver (`resolver.py`): turns declarations and raw references into the graph, outside names into external refs; the scope chain also finds scoped global aliases (`ns.func`), and alias targets may carry their own scope; paths through a module's path map, its suffixes and a dropped extension; a file's exported names (re-exports, default, `export *`) followed for members; paths no file matched kept for diagnose; page globals: `shared` refs resolve to a top-level name of another classic script loaded by the same HTML page (`link_pages`, `resolve_shared`)
- File kinds (`filekinds.py`): the one name -> kind map (Code, Scene, Configuration, Data, Build, Web page, Docs; unknown = Code if a language read it, else Data), node `file_kind` set at scan; `levels.py` puts supporting files (not code or scenes) one level lower, `views.py` `hide_file_kinds` / `file_kinds` counts, CLI `--hide-file-kind`, the viewer's kind chips in the types strip
- Level guesser (`levels.py`): rough first guess of node levels; app starts and hubs (too many connections, `hub` flag + `hub_degree`, `hub_threshold` setting) level 1, standalone scripts (tools) below them
- Settings table (`app_settings.py`): the one list of every app setting (name, kind, parser, rescan or not, one-line help) that `settings`, its error text and printout, `rescan --setting` and the AI guide's generated settings list read; item lists (`domains`, `loaded_by`, `library`, `tracks`) share `name=[json]`/`+=`/`-=` (`changed_item_list`); add a setting there only
- App scan settings (`apps.py`, `<data>/settings.json`; `coderstanding settings`): per-app options chosen before scanning: `hub_threshold`, `max_level`, `exclude` (globs of files left out, `vendor.py`), `include` (folders/globs of git-ignored files scanned anyway, `filewalk.list_files`), `function_macros` ({macro: name template} making `MACRO(args) { body }` a function, `cpp.expand_function_macros`; reaches readers by `LanguageModule.configure`, cached per setting via `cache_name`); `rescan --setting key=value` overrides them for one run without saving (`parse_setting`); the file also holds `levels` ({count, names}: how many levels and what they are called, `views.level_scale`, the one place for level names; `settings levels=Domains,App,...`, viewer "Levels…", `PUT /api/levels`; deeper classes clamp to the last level in `effective_level`; never rescans); the same file also holds the app's warning `rules` and architecture `layers` (never trigger a rescan; `Notes.rules` carries them to views); the file also holds `loaded_by` pattern rules ({loaded_by, files glob, how}, `apps.loaded_rules`) and default-domain folder rules ({files glob, domain}, `apps.domain_rules`; `Notes.domain_of`/`domain_and_author` = note first, then the first rule via `checks.first_rule_match`; shown as `domain_by: "rule"`; edit settings.json)
- Entry kinds (`model.py` `ENTRY_MECHANISMS`, `entry_flags`): the one place that names how an entry point starts (godot-main, godot-main-scene, autoload, program-main, script-main); a Python `__main__.py` is `script-main`; also the source of the Start-here paths: `views.start_paths` begins at an entry class and follows the best line (hinted first, then most calls, no hubs) for 2-6 steps
- Vendor check (`vendor.py`): the one test for files that are not the app's own code (vendor/third_party folders, `*.min.*`, versioned library names, very long lines, the app's `exclude` globs); used by the class-graph scan and the text index
- Planned work (`planned.py`, DESIGN 7f): planned and added-manually classes, planned functions and hand-made lines stored as notes with `made`; `hand_graph` (the view engine's copy with them), `is_built` (THE "built" predicate: not planned, not a stub), name matching against real code (ask first, link, keep both), add/drop/link/accept, `plan_rows` (CLI `plan`, `/api/plan`), counts
- Progress tracks (`progress.py`, DESIGN 7g): the one place for "how much is done": a track = name + `of` (classes or functions picked by files glob, domain, tag, file kind, lang, tests) + `done` (a tag, a note field filled (by a person), or a fact: tested, built (`planned.is_built`), no warnings); built-in Described / Tested / Built, the app's own in settings.json `tracks`; numbers per track, per domain, per box (`add_view_progress`, `compute_view(track=)`), over a spec's links (`Cards.tree_focus`), what is not done; history per scan (`progress.jsonl` beside graph.json, written by `apps.rescan`), delta since last scan and trend; CLI `progress`, `/api/progress`
- Stub rule (`languages/stubs.py`): `is_stub(body, around)`, the one test every reader uses for a function with no real body yet (`Member.stub`)
- Code docs (`languages/doc_text.py`): header-comment extraction and trimming shared by every reader, stored as node `doc`
- package.json reader (`languages/package_json.py`): marks `bin` / `node x.js` script files as script-main
- Scan pipeline (`scan.py`): runs walk, modules (process pool on big cold scans), resolver and levels into a graph
- Scan cache (`cache.py`): per-file parse results in `.coderstanding/cache/`, so rescans only re-read changed files
- Names index (`textindex.py`, `<data>/names.json`): at scan time, per repo file (code plus docs, compose, Dockerfile, .env, shell scripts, CI/config; the walk's skip rules plus its own one rule in `build_index`: `vendor/` folders, `*.min.*` and files with a line over 1000 characters, files over 512 KB left out) its kind (src / test by testcode's rule / doc / deploy / script / config), the names on each line, string literals and env var reads/sets; per-file results in the scan cache. Queries: `search_text` (regex over every indexed line, CLI `find --text [--path prefix]`: src first, 40 full lines, then `file: N hits` per file, nothing hidden; `views.find_text` adds the enclosing unit via `unit_at`, docs the Markdown heading), `lookup`/`uses` (every line naming a name, `a/b` keys too; each row has `prose` = comment-only / backticked / help line, printed after code under `comments / help:`; docs, scripts and config print as one count line per kind unless `--all`; `textout.capped_lines` = the shared full-lines-then-per-file-counts cap), `mentions` (by kind), `env_vars` (read/set/documented with gaps), `dupes` (literals in 2+ files); the shared helper for any name search over all files
- CLI (`cli.py`, `bin/coderstanding`): command line entry, one function per subcommand (scan, add, plan (planned work and stubs, DESIGN 7f), rescan [--repo PATH] [--setting k=v] [--relevel [ai|all]] [--reset-level-names], graph [--all] (+ globals; outside-package lines are one count unless --all), zoom [--via], node [--functions], view [--via] [--focus] [--domain] [--lines explained|all] (graph and view list explained lines first), specs [--level] [--zoom], spec [--add/--set/--delete/--accept], privacy, tours, tour [--comments], comment, outline (rows are `Class#fn` targets), read [--signatures] [--context N] (Class#fn, Class, bare function name, path:line, path:A-B, path, doc.md#Heading, or a pasted `@app` ref; `readtargets.read_target_blocks`), ref "<pasted text>", setup <test file>, find [--all] [--tests] [--include-tests] [--text PATTERN], impact [--depth] [--all] (nearest tests, +N more unless --all; a class, Class#function or any name), uses [--all], env [--prefix], dupes [--all] [--tests], hotspots [--top] [--days], progress [--track] [--spec] [--all], brief, tests, warnings [--all] (+ an `outside` summary line from the stack data, `textout.outside_lines`), diagnose [--examples], curate, set, remove [--delete-data] [--delete-notes], rename); one target parser for `Name`, `A>B`, `Name#function` (`apps.parse_target`, next to the name lookup); one target resolver for every command that takes a code target (`views.resolve_target`, also `module#Class`; `resolve_unit` / `resolve_class` / `selection_id` on top; stored spec/tour/card targets use the strict `views.checked_target` through `items.stored_target`, None when lost; `views.files_named` = module stem/name to file for `read stem:A-B`, several listed): `Name`, `A>B`, `Name#function`, a bare function name (one match used, several listed), misses say did you mean via `views.suggest_targets` = `find`'s matcher (`suggest_files` for files); cards: specs/spec and memos/memo (--stage, --priority, --importance, --sort); every command that reads a map (`open_app`) takes `--repo <worktree>` and finds the current folder's worktree by itself (`apps.worktree_app`); the `note: worktree`, "map was older than the files: rescanned", stale-map and lost-notes lines print only when changed since last shown (`worktrees.changed_since_shown`, `shown.json` in the map or data folder); `HintParser` (a missing app or targets says what to type, with the registered apps)
- Code fingerprints (`fingerprints.py`): whitespace-insensitive hashes of a class, function or connection's code, computed at scan into graph.json; notes store them when written and compare later (stale marks, `Notes.stale_fields`/`confirm`)
- Notes store (`notes.py`): notes.jsonl read/write, per-field values by author name with an `ai` flag (any human value beats an AI draft; the newest human edit replaces other people's value), `human_author` = the one answer to "who is the human here" (git user.name, else the OS user) for every viewer write, keys for nodes, edges and functions (`node:A#f`), nicknames (`nicknames`, `nicknamed`: readable names for badly named classes and functions), lost notes, `clear_field` (remove one field from AI drafts or everyone's; the backup lines come back), field types and value checks (status, tags, ignore_warnings); text fields hint, description, rules, review (how to write each: Field rules); each stores its code fingerprint (`fp`), so a changed-code value is `stale` (shown by node/zoom text, `warnings`, the details panel badge + "Still true"; `set --still-true`, POST `/api/notes/still-true`); `loaded_by` / `loaded_how` fields and `Notes.loaders(graph)` (note links + app pattern rules) say which classes load a class by name; the pseudo domain `domain:*` (`overview_id`) holds the overview's flow sentence as its `description`
- View engine (`views.py`): `compute_view` = show switches (outside code, communications, tests, `lines`: "explained" marks lines with no hint on them or any hop they stand for `quiet`, `quiet_keys` = the one rule, fan-out links follow), hide-by-file-type (`show["hide_types"]`, CLI `--hide-type`; `types`/`hidden_types` in the view), levels, bindings, concrete view, owner folding, zoom, domains, domain focus (`domain=`: one domain's classes, the rest folded into faded domain cards; `Folder(card_of=)`), target focus (specs and tour steps: classes, `A→B`, `A#f`; hidden targets light their stand-ins; function targets open their class and unfade what they call (`near`; `open_near` opens those too, a tour step's `near=1`); one connection out is faded, zoom's `focus_on`), expanded classes, card badges (`badges` = per class/line spec+memo counts from `cards.link_index`), `used_by` per class (classes on the map with a line to it), `domains` = the shown domains' hint/description; the only place views are computed; also the reading helpers `outline`, `find`, `impact` (who depends on a class or function, by distance), `read_blocks`/`read_place`/`file_block`/`header_block`/`markdown_sections`/`targets_named` (line ranges `read` prints; `unit_at` = class and function around `file:line`) and `brief` (per-target data for a paste-ready brief); draws `loaded-by` lines (B to A) from `Notes.loaders`, class JSON `loaders` Hide-by-line-kind: `show["hide_kinds"]`, CLI `--hide-kind` (a line goes only when all its kinds are hidden).; `impact` also lists the test and doc lines naming the unit (names index), `name_impact` = impact of a plain name (constant, env var, settings key) through the code units whose lines use it
- Function fan-out (`fanout.py`): the step of `compute_view` that re-attaches lines to the functions of expanded classes (merged per endpoint pair, derived lines by first/last hop) and lists their functions, fields and public `properties`
- Markdown item store (`items.py`): one Markdown file per item in `<data>/<kind>/<id>.md` (tours, specs; diagrams later): front matter (small YAML subset; a plain block value takes the whole line) + body, `## Title` sections, read/write/list/search, wiki-link names, unknown targets (like lost notes), targets as view ids (`focus_ids`), ids from titles (`slug`, `free_id`); no kind-specific fields
- Cards (`cards.py`): specs and memos (UI: Notes; "memo" so it never mixes with notes.py) on the item store, one store for both kinds: a `Kind` declares only its folder, stages and default stage (spec: idea → todo → in-progress → review → implemented, dropped; memo: todo → in-progress → done, na = N/A default); old `status`/`classes` files read as stage/links; fields title, parent, level (parent + 1 unless set deeper), stage, work priority and importance (high/medium/low), links (classes, `A>B` lines, `A#f` functions), text, sibling order; per-field authors (`ai` = fields still AI drafts; a human edit or Accept wins, AI writes keep human fields), checks (unknown links, missing parent, cycles refused, level never shallower than the parent), unreadable files listed not dropped; the sidebar's data (folding `+N finer`, zoom, breadcrumbs, search, stage/priority filters and sorts with paths); target keys `spec:<id>` / `memo:<id>`; `link_index` = the one reverse index (class or line -> linking cards) for view badges, details panel and `node`/`zoom`; delete moves children up
- Location refs (`refs.py`, DESIGN 7e): the `@<app> <target> [(<hint>)]` text line for lines, classes, functions, headings, tour steps, comments, specs and memos: parse / find in pasted text / write (`tests/fixtures/refs.json` = the shared examples) / resolve (moved-unit hint offsets) / print; behind `ref`, `read "@app ..."` and GET /api/ref
- Read targets (`readtargets.py`): what `read` prints for one target in any form (`path:A-B`, `path`, `doc.md#Heading`, `Class#f`); shared by `read` and refs
- Comments (`comments.py`): threads on any item (a tour, a step; later specs, classes): replies, resolve/reopen, author names with an `ai` flag, optional code line (an offset in a class/function anchor, follows edits) or quoted words; `<id>.comments.jsonl` next to the item, one per line, sorted, union-merge friendly (newest copy wins); lost targets listed, never dropped
- Tours (`tours.py`): guided code walks on the item store: steps with stable keys, targets, code excerpts anchored on a class/function (`+a..+b` offsets, marks) resolved to today's lines, line notes (popup callouts on excerpt lines, offsets like marks, optional `cue` words; `tour --note/--drop-note`), stale = excerpt digest changed (`fingerprints.digest`), Still true / accept / AI drafts like notes, recordings in `tours/<id>/<key>.rec.*`; the viewer's JSON; a tour with `start: true` is a Start-here path (`draft_starts` = AI drafts of `views.start_paths`, CLI `tour <app> --draft-start`, `tours` marks them); `view:` options for the tour and per step (`clean_view`, `set_view`, CLI `tour --view k=v` / `--step N --view`), opaque here: the viewer's table knows them
- Slim text (`textout.py`): prints `compute_view` output (and the warnings list) in the terse text format (explained lines first), and the outline / find / impact / brief / read texts; function lines of expanded classes; `view_text` = the whole screen as text with its command (CLI `view` and the viewer's Copy for AI); the tour texts (`format_tours`, lean `format_tour`, `tour_markdown` = the one Markdown export for CLI `--md` and the API); the card texts (`format_cards` tree/hits, `format_card`, `linked_lines` for node/zoom); `uses` / `env` / `dupes` texts and `places_text` (`file:l1,l2` lists); `graph <app> 0` prints the overview (sentence, one line per domain) before the lines
- Word matching (`wordmatch.py`): split names into words (snake, Camel, SCREAMING, file names), word quality (exact/stem, part of a word, one typo) and close-name suggestions; `find` ranks with it (`views.find`: class, function and field names, notes, code docs and linked spec/memo/tour text via `cards.linked_texts`; `--tests` adds callers and nearest tests)
- Globals + test setup (`views.py` `globals_list` / `setup_of`, `textout.py` `globals_lines` / `format_setup`; readers set `Mark.global_name/kind` and `FileResult.lookups`, stored as node `global_*` / `lookups`): every autoload / class_name / [GlobalClass] with how tests and code reach it (name or `root.get_node(..)` lookups), shown at the end of `graph` and in `outline`; `setup` = a test file's hooks, helpers, bases, support nodes, globals and the fixtures its sibling tests have that it lacks
- Test code (`testcode.py`): the one rule for which files are tests (and `function_role`: test / hook / helper function names) (flag `test`), which tests cover a node (a test using a language module, a `LanguageModule` subclass, also covers the other code in that module's file and what that code uses), `tests_using` (tests calling a function, else covering its class; `function_test_index` = the one (class, function) -> calling test files index), which to rerun after a change (`retest_files` = own tests plus any dependents' tests; `views.diff_tests` + `filewalk.git_changed_lines` map a git diff to units and the narrowest tests for `tests --diff` (per function: tests calling it, else its class's; a dependents' tests only when a def line changed; `is_runnable_test` keeps `helpers.py`/`conftest.py` out), `textout.format_diff_tests` prints every one)
- Checks (`checks.py`): per-node warnings after the scan (unused, god class, cycle, unsure, unresolved, parse-error = files the grammar could not fully parse, from `graph.diagnostics["parse_errors"]`; `unresolved_by_node` feeds `warnings --names`; and the Godot loose ends signal-unconnected / signal-unemitted / bad-handler / autoload-unused, read from emit / signal / member data of the graph); warnings a class's notes or the app's warning rules (folder glob + optional lang/kind + kinds to ignore, `rules` command) ignore are split off, each with its reason (`ignore_reason` is the one decider); a cycle needs 2+ unignored members to be listed; architecture rules (`layers` setting: from/to = folder glob, `domain:`, `tag:`; forbid/only; optional edge kind and why) give the `from` class a `layer` warning per bad real line (`apply_layers`, run again on load since settings and notes are not part of a scan); a class with a loaded-by link is not `unused` (`apply_note_warnings` also re-decides it on load)
- Library rules (`library.py`): the `library` setting; marks classes matching a path glob, name pattern, tag or domain as outside code when the map is loaded (`apps.App.checked`), so levels, hubs and warnings cover own code only
- Hotspots (`views.py` `hotspots`, `filewalk.git_churn`, `textout.format_hotspots`): classes and modules ranked by size x commits on their file in the last N days x untested (testcode's rule); git runs through `filewalk.git_output`
- Child processes (`procs.py`): `run_quiet`/`popen_quiet`/`quiet_kwargs`, the only place that starts a subprocess (no console window on Windows; a test fails on any other call)
- Apps (`apps.py`): app registry, data folder, `rescan` (the only scan entry besides Add project and `refresh_map`; one-run setting overrides; records the files' signature; prunes stale worktree maps), worktree maps (`worktree_app`: an `App` whose root is another git worktree and whose graph/cache (`map_dir`) are its own, notes and settings the app's, except an in-repo `.coderstanding/` data folder, which becomes the worktree's own (seeded once with main's untracked notes/settings) so writes never land in main; `refresh_map` = the one freshness check for every reading command, main map or worktree: rescans (warm cache) when the files' signature changed, else says "map is older than the files (N changed): rescan" if it cannot (read-only data, missing folder); `prune_worktree_maps`) and `relevel` (opt-in `--relevel`: clear AI or all per-class level notes after a rescan, with a backup; level names kept unless asked) and `load_graph` (reads the saved graph, never scans; the CLI's `open_app` refreshes first, the server never does), short-name lookup; `data_for_add` = the one rule for a new app's data folder (given, existing, an in-repo folder that already holds own files, else `~/.local/share/coderstanding/<name>`; an unregistered folder passed to `rescan`/`find_app` follows the same rule); app manager functions shared by CLI and API: `app_details`, `remove_app` (unregister; optionally delete the generated files, and the user's own files only when asked; never outside the data folder or in the repo beyond `.coderstanding/`), `rename_app`, `clean_name` `settings` also edits the item lists `domains`, `loaded_by`, `library`, `tracks` (`RULE_LISTS`, from the settings table).
- Java reader (`languages/java.py`): tree-sitter reader for `*.java` (types, nested types, members with line ranges, field/constructor/method type refs, calls, imports, `main`); ids `package.Outer.Inner`, the same scheme as Kotlin
- C# reader (`languages/csharp.py`): tree-sitter reader for `*.cs` (types, refs, Godot C# idioms incl. `EmitSignal` / `Connect` / `Sig += h`)
- Shell reader (`languages/shell.py`): tree-sitter reader for `*.sh` / `*.bash` (script = module node, `#!` makes it a `script-main` tool; functions as members with stubs; calls to its own functions; `source` / `.` and running another repo script as dependency refs; outside commands as plain refs the stack reader counts as platform names; env vars come from the names index `SHELL_ENV`, which now wins over `CODE_ENV` for scripts)
- Kotlin reader (`languages/kotlin.py`): tree-sitter reader for `*.kt` / `*.kts` (package-qualified types, companions as children, a `FooKt` module node for top-level code, constructor `val`s as held fields, calls, imports/aliases, extension functions); Gradle files and `libs.versions.toml` go to the stack reader (`stack.py` `read_gradle`)
- Tree-sitter helpers (`languages/ts_util.py`): parser setup, node text/line, child/descendant iteration (iterative, deep-tree safe) shared by every tree-sitter reader
- C/C++ reader (`languages/cpp.py`): module node per header/source pair, namespaced types, fields/bases/calls, free functions and includes via global aliases, typedef/using aliases (typedefs of basic types: `Target.basic`, dropped by the resolver, not unresolved; compiler words blanked before parsing, `COMPILER_WORDS`; decompiler output names as built-ins, `DECOMPILER_TYPES` / `DECOMPILER_INTRINSICS`; non-static `.c` function definitions are global names; calls to the file's own listed functions and a class's own methods are own calls)
- HTML reader (`languages/html.py`): module node per page, `<script src>` / `<link href>` imports; its classic (non-module) scripts are listed as `page_scripts`
- Python reader (`languages/python.py`): module nodes, classes, bases, fields, imports anywhere in the file (functions, try/except, `TYPE_CHECKING`), calls (incl. own calls: module functions calling each other, `self.x()`/`cls.x()`), type hints
- JS/TS reader (`languages/javascript.py`): module nodes, classes, interfaces, enums, extends/implements, fields (incl. parameter properties, `inject()`), imports/require/`import()` (also inside functions), classic browser scripts' top-level names as `page_globals` + `shared` refs for bare names, re-exports and default exports, calls, JSX components, decorators, type positions, events; top-level functions (also inside a top-level IIFE) as module members; own calls (module functions calling each other, `this.x()`)
- Diagnose (`diagnose.py`, `coderstanding diagnose [--examples]`): why classes look unconnected, privacy-safe: unresolved import paths sorted into reasons at scan time (`graph.json` `diagnostics`), printed as counts, optional anonymised examples
- GDScript reader (`languages/gdscript.py`): tree-sitter reader for `*.gd` (scripts, inner classes, constructors, preload names, inferred types, signals, emits (`emit()`, `emit_signal`), connects incl. string form, base-script names)
- Godot project + scene reader (`languages/godot.py`): `project.godot` autoloads and main scene, `.tscn` scene nodes with their children and connections
- Godot file formats (`godot_files.py`): parses Godot config files (project.godot, plugin.cfg) and `.tscn` scenes; a GDScript file's `class_name` (no tree-sitter)
- Stack reader (`stack.py`): tech stack and outside dependencies from project files; maps outside refs to outside nodes, a counted godot-api entry, an `outside` bucket (host-program modules, asset files) or unresolved (`is_unresolved` is the one decider, so warnings, stack and viewer agree; its tables hold the platform and standard names: Android `android.*`, Kotlin standard types, Node `node:*`, JS globals, `.gdshader` assets; `unresolved_names` = one count per name); also finds communications nodes (sockets / network endpoints: `COMM_TYPES`, `comm_for`, ids `comm:<owner>#<field>`; GDScript `@rpc` mode on members); shared comm pieces for the text passes: `comm_node`, `add_comm_node`, `OwnerIndex` (the class holding a file line), `link_caller` (a caller's line to a comm node)
- HTTP routes (`http_routes.py`): finds server route literals and client URL literals in py/js/ts/gd, adds `http.server` / `http.client` comm nodes through the Stack reader's `add_comm_node`, links clients to the server route they call
- Member visibility (`model.is_public`, `Member.public`): the one rule per language for which fields other code can use; the Properties list, class counts and outline show only those
- Network messages (`rpc_messages.py`): remote-callable functions (`Member.rpc` = mode words, GDScript `@rpc`) as `rpc` comm nodes, one per (handling class, sending class) whose rows are the messages that sender sends (unsent ones in a "(not sent)" box), with direction from the mode (`rpc_direction`), senders from a text pass (`SEND_READERS` per file type), sender -> message -> handler lines; `node_messages`/`message_directions` for the view engine and text
- Layout store (`layout.py`): saved class spots and pins in `.coderstanding/layout.json`
- Hub (`hub.py`): every app the local server shows: registry list with last scan/size/errors (`details` for the app manager), per-app Api, niced background scans (`coderstanding rescan` child; `scan_options` passes one-run settings/relevel from `POST /api/rescan` as child flags; viewer Projects… -> "Redo levels…"), register-and-scan a folder, remove and rename
