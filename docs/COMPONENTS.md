# Components

One line each: name and short description.

- Graph model (`scanner/coderstanding/model.py`): nodes (with size and warnings), edges, calls (per calling function and called member), members (functions carry first and last line), locations and their merge rules; a node's function names and a call's calling/called function
- Graph file (`graph_json.py`): read and write graph.json (another scanner version's map is refused, so it gets rescanned); `graph_summary` = counts and scanner version without building the model
- Language module contract + registry (`language.py`): what a language reader gets and returns, and how it plugs in; modules may reset in-memory state in `start_scan()`; `ctx.file_exists()` probes a repo file (a missing one becomes a cache dependency)
- Language modules (`languages/`): one reader per language, auto-loaded; C# `[GlobalClass]` classes are global aliases so GDScript finds them by bare name
- Paths (`paths.py`): repo-relative path helpers (res://, relative paths, Godot root)
- File walk (`filewalk.py`): finds the files to scan and which modules read them
- Resolver (`resolver.py`): turns declarations and raw references into the graph, outside names into external refs; the scope chain also finds scoped global aliases (`ns.func`), and alias targets may carry their own scope
- Level guesser (`levels.py`): rough first guess of node levels; app starts and hubs (too many connections, `hub` flag + `hub_degree`, `hub_threshold` setting) level 1, standalone scripts (tools) below them
- App scan settings (`apps.py`, `<data>/settings.json`; `coderstanding settings`): per-app options chosen before scanning, e.g. `hub_threshold`; the same file also holds the app's warning `rules` and architecture `layers` (never trigger a rescan; `Notes.rules` carries them to views)
- Entry kinds (`model.py` `ENTRY_MECHANISMS`, `entry_flags`): the one place that names how an entry point starts (godot-main, godot-main-scene, autoload, program-main, script-main)
- Code docs (`languages/doc_text.py`): header-comment extraction and trimming shared by every reader, stored as node `doc`
- package.json reader (`languages/package_json.py`): marks `bin` / `node x.js` script files as script-main
- Scan pipeline (`scan.py`): runs walk, modules (process pool on big cold scans), resolver and levels into a graph
- Scan cache (`cache.py`): per-file parse results in `.coderstanding/cache/`, so rescans only re-read changed files
- CLI (`cli.py`, `bin/coderstanding`): command line entry, one function per subcommand (scan, add, graph, zoom [--via], node [--functions], view [--via] [--focus], tours, tour, outline, find [--all], impact [--depth], brief, tests, warnings [--all], curate, set, remove [--delete-data] [--delete-notes], rename); one target parser for `Name`, `A>B`, `Name#function` (`apps.parse_target`, next to the name lookup)
- Code fingerprints (`fingerprints.py`): whitespace-insensitive hashes of a class, function or connection's code, computed at scan into graph.json; notes store them when written and compare later (stale marks, `Notes.stale_fields`/`confirm`)
- Notes store (`notes.py`): notes.jsonl read/write, per-field values by author name with an `ai` flag (any human value beats an AI draft), keys for nodes, edges and functions (`node:A#f`), lost notes, field types and value checks (status, tags, ignore_warnings); text fields hint, description, rules, review; each stores its code fingerprint (`fp`), so a changed-code value is `stale` (shown by node/zoom text, `warnings`, the details panel badge + "Still true"; `set --still-true`, POST `/api/notes/still-true`)
- View engine (`views.py`): `compute_view` = levels, bindings, concrete view, owner folding, zoom, domains, target focus (specs and tour steps: classes, `A→B`, `A#f`; hidden targets light their stand-ins; function targets open their class), expanded classes; the only place views are computed; also the reading helpers `outline`, `find`, `impact` (who depends on a class or function, by distance) and `brief` (per-target data for a paste-ready brief)
- Function fan-out (`fanout.py`): the step of `compute_view` that re-attaches lines to the functions of expanded classes (merged per endpoint pair, derived lines by first/last hop) and lists their functions and fields
- Markdown item store (`items.py`): one Markdown file per item in `<data>/<kind>/<id>.md` (tours; specs and diagrams later): front matter (small YAML subset) + body, `## Title` sections, read/write/list/search, wiki-link names, unknown targets (like lost notes); no kind-specific fields
- Tours (`tours.py`): guided code walks on the item store: steps with stable keys, targets, code excerpts anchored on a class/function (`+a..+b` offsets, marks) resolved to today's lines, stale = excerpt digest changed (`fingerprints.digest`), Still true / accept / AI drafts like notes, recordings in `tours/<id>/<key>.rec.*`; the viewer's JSON
- Slim text (`textout.py`): prints `compute_view` output (and the warnings list) in the terse text format, and the outline / find / impact / brief texts; function lines of expanded classes; `view_text` = the whole screen as text with its command (CLI `view` and the viewer's Copy for AI); the tour texts (`format_tours`, lean `format_tour`, `tour_markdown` = the one Markdown export for CLI `--md` and the API)
- Test code (`testcode.py`): the one rule for which files are tests (flag `test`), which tests cover a node, which to rerun after a change (`retest_files` = own tests plus any dependents' tests)
- Checks (`checks.py`): per-node warnings after the scan (unused, god class, cycle, unsure, unresolved, and the Godot loose ends signal-unconnected / signal-unemitted / bad-handler / autoload-unused, read from emit / signal / member data of the graph); warnings a class's notes or the app's warning rules (folder glob + optional lang/kind + kinds to ignore, `rules` command) ignore are split off, each with its reason (`ignore_reason` is the one decider); a cycle needs 2+ unignored members to be listed; architecture rules (`layers` setting: from/to = folder glob, `domain:`, `tag:`; forbid/only; optional edge kind and why) give the `from` class a `layer` warning per bad real line (`apply_layers`, run again on load since settings and notes are not part of a scan)
- Apps (`apps.py`): app registry, data folder, rescan-if-stale, short-name lookup; app manager functions shared by CLI and API: `app_details`, `remove_app` (unregister; optionally delete the generated files, and the user's own files only when asked; never outside the data folder or in the repo beyond `.coderstanding/`), `rename_app`, `clean_name`
- C# reader (`languages/csharp.py`): tree-sitter reader for `*.cs` (types, refs, Godot C# idioms incl. `EmitSignal` / `Connect` / `Sig += h`)
- Tree-sitter helpers (`languages/ts_util.py`): parser setup, node text/line, child/descendant iteration (iterative, deep-tree safe) shared by every tree-sitter reader
- C/C++ reader (`languages/cpp.py`): module node per header/source pair, namespaced types, fields/bases/calls, free functions and includes via global aliases, typedef/using aliases
- HTML reader (`languages/html.py`): module node per page, `<script src>` / `<link href>` imports
- Python reader (`languages/python.py`): module nodes, classes, bases, fields, imports, calls, type hints
- JS/TS reader (`languages/javascript.py`): module nodes, classes, extends/implements, fields, imports/require, calls, events
- GDScript reader (`languages/gdscript.py`): tree-sitter reader for `*.gd` (scripts, inner classes, constructors, preload names, inferred types, signals, emits (`emit()`, `emit_signal`), connects incl. string form, base-script names)
- Godot project + scene reader (`languages/godot.py`): `project.godot` autoloads and main scene, `.tscn` scene nodes with their children and connections
- Godot file formats (`godot_files.py`): parses Godot config files (project.godot, plugin.cfg) and `.tscn` scenes; a GDScript file's `class_name` (no tree-sitter)
- Stack reader (`stack.py`): tech stack and outside dependencies from project files; maps outside refs to outside nodes, a counted godot-api entry, or unresolved
- Layout store (`layout.py`): saved class spots and pins in `.coderstanding/layout.json`
- Hub (`hub.py`): every app the local server shows: registry list with last scan/size/errors (`details` for the app manager), per-app Api, niced background scans (`coderstanding rescan` child), register-and-scan a folder, remove and rename
- Server (`server.py`, `coderstanding serve`): serves every registered app (`?app=`, `/api/apps[?details=1]`, `/api/rescan`, POST `/api/apps`, DELETE `/api/apps/<name>?data=&notes=`, PATCH `/api/apps/<name>`; loads an app, rescans when stale), then serves the viewer and the JSON API (view with expand/focus, text, node, stack, layout, notes write/accept, meta, tours: list/get/.md/put/still-true/accept/audio) on 127.0.0.1; it is also the local helper behind the hosted page: CORS + Private Network preflight for one allowed origin (`--allow-origin`) on every route, writes refused from other origins, other host names or without a JSON body (tour recordings: raw audio/webm|ogg, max 5 MB)
- App picker (`viewer/apps.js`): toolbar app switch (#app URL, last app, per-app camera/level kept across switches), Refresh, `[`/`]` (UI says "project"; ids/API keep "app"); `apiBase` = the one place that picks where every API call goes (this server, or the local helper on the hosted page, found through `hosted.json`), `url`/`request` = every API fetch; app manager modal (Projects…: every project's folders, scan facts, notes/tours counts; Open, Refresh, Rename, Remove with an in-modal keep/delete choice; "Add project…" in the footer registers and scans a folder); "Running on this PC" label, and the empty page (no projects, or the hosted page's start-the-helper how-to)
- Hosted page config (`deploy/hosted.json`, `viewer/hosted.json`): where the hosted page looks for the local helper (none for a local serve page)
- User config (`userconfig.py`): the `~/.config/coderstanding/` folder and per-user settings that never live in code (`hosted.json`: the hosted page origin)
- Public export (`scripts/export-public.sh`, `scripts/public_check.py`, `public-exclude.txt`): builds the public copy from a commit (excludes, `private:start`/`private:end` blocks, `public-line:` lines), refuses on personal strings (generic patterns + a denylist outside the repo), commits it to a separate local repo
- Viewer (`viewer/`): static page that draws the server's views with Cytoscape.js (graph tab, details panel with editable notes, warnings, size, tested-by, status/tag highlight, zoom (double-click), layout modes, stack tab, Copy for AI, start badges, ignore warnings, names that tell clashing classes apart, class-line bends and label spots)
- Tours player logic (`viewer/tours.js`): spoken text and word spans (a link speaks as several words), the word-count timeline, voice picking for the page language, recorder format, and `StepPlayer` (recording, else browser voice with boundary tracking and seek-by-word restarts, else a silent clock; late voices, missing boundary events, a voice that never starts); pure, tested with `node --test`
- Tours tab (`viewer/tour_view.js`): tours list with search and .md links, player bar (Back/Play/Next, dots, speed, voice, seek bar, source chips), step panel with follow-along word highlight, code pane with stale bar and Still true, tour editor (add step from the graph selection, reorder, delete, Save/Done = PUT), recording upload, Save as Markdown, Step as AI text (the `.txt` route) with Copy for AI, keys and `?tab=tours&tour=&step=&edit=1`; borrows the graph tab's canvas and asks the server's view with the step's focus
- Viewer layout (`viewer/layout.js`): auto spots for classes by method (layered bands per level (default), organic force layout, hub rings, grid; grid above 1500 classes), level-by-level seeding, outside code beside its users, tools in a left column, placing around fixed (saved/pinned) spots; lines bent around boxes (short detours only) and greedy label spots; pure, tested with `node --test`
- Viewer fan-out and box faces (`viewer/fanout.js`): every class box's face (header, toggle triangle, start and hub badges, warning mark), open boxes with scrolling, filterable function and field lists, fan-out lines (busy class pairs share a trunk) in two SVG layers over/under the graph, their labels, function hover/select and its details
- Details-panel lists (`viewer/lists.js`): merge calls by member name and fold long lists (first 8, then a native "Show all N" details); used by every details-panel list
- Viewer panels (`viewer/panels.js`): drag/keyboard resizing of the side panels, widths kept per browser
- Mock-up fixture (`tests/fixtures/fanout_mock/`): the approved fan-out mock-up's sample as a Godot project, for side-by-side viewer checks
- Viewer end-to-end checks (`tests/e2e/`): `cdp.mjs` = tiny DevTools-protocol client (headless Chromium with extra switches, e.g. `--enable-speech-dispatcher`; real mouse/keys, clipboard), `run.mjs` = the scripted checks of every viewer control plus layout quality (readable zoom, no overlaps, short bends, no piled labels), `fixture/` = their sample app (`.coderstanding/tours/first-steps.md`: a tour the checks copy into the data folder; speech runs at volume 0, a fake microphone records)
- Claude hook (`scripts/claude-hook.py`): SessionStart note and once-per-session PreToolUse hint (Grep/Glob/Read/Bash search) pointing Claude at Coderstanding inside registered repos and their worktrees; stdlib, reuses `apps.load_registry`, never blocks
- Helper service + tray (`deploy/systemd/`, `scripts/install-helper.sh`, `scripts/helper_tray.py`, `scripts/helper_status.py`): systemd user units that start the local helper at login and a Qt tray icon polling `/api/apps` (up / scanning / down icon, tooltip, start/stop/log menu); `helper_status.py` is the pure listing-to-icon/tooltip logic
